## Added

- `/season_pass` with a private seven-tier seasonal reward track from 100 to 3,000 season points.
- `/claim_season_pass` for atomic collection of every newly unlocked tier.
- Fixed token rewards that never add season points and therefore cannot recursively unlock the pass.
- PostgreSQL table `pvp_season_pass_claims` and migration `0011_season_pass`.
- Telegram command-menu registration and v0.20 onboarding/privacy handlers.

## Reliability

- Claims lock the user profile and progression wallet in one transaction.
- A composite primary key `(user_id, season, tier_id)` makes repeated requests idempotent.
- Later progress grants only newly unlocked tiers without paying older tiers again.
- Each season has an independent pass and claim history.
- Tier order, requirements and rewards are deterministic and code-defined.
- Missing wallets start safely at zero points and zero tokens.

## Privacy and compatibility

- Claim rows store only user ID, season, fixed tier ID, points requirement, token reward, claimed point balance and timestamp.
- Topics, match IDs, arguments, transcripts, verdicts and judge-score payloads are never copied into season-pass storage.
- Pass rewards add only tokens and do not modify season points, Elo, matchmaking, judging or match outcomes.
- Claim rows use `ON DELETE CASCADE` and disappear with the user profile.
- Existing v0.19 goal rewards, v0.18 goals, v0.17 record books and all previous progression features remain compatible.
- No new runtime dependency, OpenAI request or background task is introduced.
