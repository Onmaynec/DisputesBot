## 🎯 Персональные PvP-вызовы

Вызовы сохраняются в PostgreSQL и не исчезают после перезапуска бота.

```text
/challenge тема                         reply на сообщение соперника
/challenge 123456789 тема               вызвать известного пользователя по ID
/challenges                             входящие и исходящие вызовы
/accept_challenge a1b2c3d4e5f6          принять вызов
/decline_challenge a1b2c3d4e5f6         отклонить входящий вызов
/cancel_challenge a1b2c3d4e5f6          отменить исходящий вызов
```

Пользователь, указанный по ID, должен уже иметь профиль в боте. При reply профиль
создаётся или обновляется из Telegram-данных сообщения.

### Жизненный цикл

1. Автор создаёт вызов с темой и получает короткий ID.
2. Соперник видит вызов в `/challenges` и получает личное уведомление, если бот может
   отправить ему сообщение.
3. При принятии вызов временно переходит в состояние `accepting`.
4. Существующий Redis-движок атомарно проверяет занятость игроков и создаёт матч.
5. После успешного старта вызов связывается с `match_id` и становится `accepted`.
6. При ошибке запуска резервирование снимается, и вызов снова можно принять.

В одну сторону или навстречу для одной пары и сезона может существовать только один
активный вызов. Зависшая резервация автоматически восстанавливается через пять минут.

## ⚔️ Соперники и личные встречи

```text
/rivals                     пять самых частых соперников
/head_to_head 123456789      личные встречи с игроком
/head_to_head                reply на сообщение игрока
```

`/head_to_head` показывает общий и рейтинговый счёт, Elo-дельту, текущую серию,
дату последней встречи и последние темы. Данные строятся только по завершённым матчам,
в которых участвовал сам запрашивающий пользователь.

## 🔐 Публичность PvP-профиля

Профиль приватный по умолчанию. Собственная карточка всегда доступна владельцу.

```text
/pvp_profile                         своя карточка
/pvp_profile 123456789               чужая публичная карточка
/pvp_profile                         reply на сообщение игрока
/profile_visibility                  текущая настройка
/profile_visibility public           разрешить просмотр
/profile_visibility private          скрыть профиль
```

Публичная карточка содержит Elo, место, сезонную статистику, очки и экипированную
косметику. Баланс токенов показывается только владельцу. Блокировка в любую сторону
запрещает просмотр профиля и персональные вызовы.

## 🛍 PvP-косметика

```text
/shop                 каталог, цены и требования
/buy sharp_mind       купить предмет по item ID
/inventory            показать купленные предметы
/equip sharp_mind     экипировать титул или значок
/unequip title        снять титул
/unequip badge        снять значок
```

Токены выдаются за daily-задания. Косметика не влияет на Elo, подбор соперника,
судейство или исход матча.

## 🎯 Ежедневные задания и сезон

```text
/daily        показать задания, прогресс и награды
/daily_claim  получить завершённые награды
/season       токены, очки, уровень и серии
/season_top   лидерборд сезонного прогресса
```

Набор заданий вычисляется по progression-дате и переживает перезапуск. Повторный claim
не начисляет награду второй раз.

## 🛡 Безопасность

| Команда | Назначение |
|---|---|
| `/block` | Заблокировать пользователя reply-сообщением |
| `/block user_id` | Заблокировать по Telegram ID |
| `/unblock user_id` | Удалить из blocklist |
| `/blocked` | Показать blocklist |
| `/report категория комментарий` | Пожаловаться на матч |
| `/my_reports` | Показать свои жалобы |

Blocklist проверяется при открытых приглашениях, очереди, рематчах, персональных
вызовах, принятии вызовов и просмотре чужого профиля.

## 🧠 Надёжность v0.10

- вызовы сохраняются отдельно от краткоживущих Redis-приглашений;
- создание вызова идемпотентно для пары и сезона;
- принятие использует промежуточное состояние `accepting`;
- Redis user-locks исключают два одновременных матча одного пользователя;
- неудачный старт возвращает вызов в `pending`;
- истёкшие вызовы закрываются при следующем обращении;
- матчи, Elo и судейство используют проверенный движок v0.5–v0.9;
- новых runtime-зависимостей нет.

## 🚀 Запуск

```bash
git clone https://github.com/Onmaynec/DisputesBot.git
cd DisputesBot
cp .env.example .env
```

Заполните `BOT_TOKEN`, `OPENAI_API_KEY` и при необходимости `MODERATOR_USER_IDS`.

```bash
docker compose up -d postgres redis
pip install -e ".[dev]"
alembic upgrade head
python -m bot.main
```

Полный запуск в Docker:

```bash
docker compose up --build -d
```

## 📦 Релизы

Workflow `.github/workflows/release.yml` запускается после push в `main`:

1. читает версию из `pyproject.toml`;
2. проверяет наличие GitHub Release с соответствующим тегом;
3. собирает wheel и source distribution;
4. извлекает notes текущей версии из `CHANGELOG.md`;
5. создаёт тег `vX.Y.Z` и GitHub Release с артефактами.

Повторный push с той же версией безопасен: существующий Release не создаётся заново.

## 🔐 Приватность

`/delete_me` удаляет профиль, архивы, PvP-рейтинг, историю матчей, blocklist,
progression wallet, daily claims, косметику, публичность, входящие и исходящие вызовы,
настройки и активные Redis-сессии. Жалобы остаются обезличенными аудиторскими записями.

Вызов хранит только ID участников, сезон, тему, статус, срок действия и связанный
`match_id` после принятия. Аргументы будущего матча в challenge-table не сохраняются.
