# ⚔️ DisputesBot v0.2

**Telegram-бот для тренировки дебатов, логики и аргументации**

Бот всегда занимает противоположную позицию, отвечает одним аргументом за ход, разбирает слабые места и проводит турниры с независимым судейством.

## ✨ Что появилось в v0.2

- 🔒 Блокировка параллельных запросов отдельно для каждого пользователя.
- ⏱ Rate limiting с настройкой лимита и временного окна.
- 📏 Ограничения длины темы и пользовательского аргумента.
- 💾 Восстановление активных споров после перезапуска через Redis.
- 🧾 Строгие Pydantic-схемы для всех ответов модели.
- ⚖️ Независимый судья с отдельной моделью и анонимными сторонами A/B.
- 🆔 Лидерборд по неизменяемому Telegram `user_id`, а не username.
- 🎚 Сложности: **новичок**, **опытный**, **эксперт**.
- 🛑 `/cancel` — завершение активного спора.
- 📊 `/stats` — личные результаты и состояние текущего спора.

## 🎮 Возможности

- `/debate [тема]` — обычный спор с противоположной позицией бота.
- `/role [роль]` — философ, юрист, шутник или циник.
- `/difficulty [уровень]` — изменение глубины и жёсткости аргументации.
- Один логичный контраргумент за сообщение: тезис, объяснение и пример.
- Разбор сильных и слабых сторон после каждых пяти аргументов пользователя.
- `/summary` — структурированное резюме тезисов обеих сторон.
- `/judge` — анонимное независимое судейство с баллами обеих сторон.
- `/tournament` — три раунда, по три аргумента каждой стороны.
- Обратная связь после каждого турнирного раунда.
- Финальная оценка: логика, аргументация и креативность по 10 баллов.
- `/leaderboard` — топ результатов из JSON-файла.

## 🧠 Как устроено независимое судейство

Перед оценкой история преобразуется в диалог участников **A** и **B**. Порядок сторон выбирается случайно, поэтому судья не знает, где пользователь, а где бот. Для судейства можно задать отдельную модель через `OPENAI_JUDGE_MODEL`.

Строгие Structured Outputs валидируются Pydantic. Некорректный ответ модели не записывается в историю как успешный ход.

## 💾 Хранение данных

Redis хранит:

- активные сессии и полную историю спора;
- выбранную роль и сложность;
- временный набор тем турнира;
- ключи распределённых блокировок и rate limit.

Активная сессия по умолчанию живёт семь дней и восстанавливается после перезапуска бота. JSON-лидерборд остаётся простым переносимым хранилищем результатов.

Лидерборд v0.2 использует `user_id` как ключ:

```json
{
  "123456789": {
    "user_id": 123456789,
    "username": "username",
    "display_name": "User Name",
    "tournaments": 3,
    "wins": 2,
    "draws": 1,
    "losses": 0,
    "best_total": 27,
    "average_total": 24.67,
    "last_scores": {
      "logic": 9,
      "argumentation": 9,
      "creativity": 8,
      "total": 26
    }
  }
}
```

Старые записи с ключами вида `@username` автоматически сопоставляются по сохранённому `user_id` при чтении и перезаписываются в новом формате после следующего результата.

## 🚀 Запуск через Docker Compose

```bash
git clone https://github.com/Onmaynec/DisputesBot.git
cd DisputesBot
cp .env.example .env
```

Заполните в `.env` как минимум:

```dotenv
BOT_TOKEN=токен_от_BotFather
OPENAI_API_KEY=ваш_api_ключ
OPENAI_MODEL=gpt-5.5
OPENAI_JUDGE_MODEL=gpt-5.5
REDIS_URL=redis://redis:6379/0
```

Запуск:

```bash
docker compose up -d --build
```

Compose запускает бота и Redis с AOF-персистентностью. Лидерборд хранится в `./data`, Redis — в отдельном Docker volume.

## 🛠 Локальный запуск

Понадобится работающий Redis:

```bash
python -m venv .venv
source .venv/bin/activate  # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env
python -m bot.main
```

## ⚙️ Настройки

| Переменная | По умолчанию | Назначение |
|---|---:|---|
| `OPENAI_MODEL` | `gpt-5.5` | Модель оппонента |
| `OPENAI_JUDGE_MODEL` | модель оппонента | Отдельная модель судьи |
| `REDIS_URL` | `redis://localhost:6379/0` | Подключение к Redis |
| `SESSION_TTL_SECONDS` | `604800` | Срок хранения сессии |
| `MAX_TOPIC_CHARS` | `300` | Максимальная длина темы |
| `MAX_ARGUMENT_CHARS` | `2500` | Максимальная длина аргумента |
| `RATE_LIMIT_REQUESTS` | `5` | Запросов на окно |
| `RATE_LIMIT_WINDOW_SECONDS` | `20` | Размер окна в секундах |
| `REQUEST_LOCK_TTL_SECONDS` | `90` | TTL распределённой блокировки |

## 📁 Структура

```text
bot/
├── config.py         # настройки окружения
├── guard.py          # блокировки и rate limit
├── handlers.py       # команды и сценарии диалогов
├── judge_utils.py    # анонимизация сторон
├── llm.py            # оппонент и независимый судья
├── models.py         # сессии, сложности и оценки
├── schemas.py        # строгие Structured Outputs
└── storage.py        # Redis-сессии и JSON-лидерборд
```

## 🔐 Примечания

- Не публикуйте `BOT_TOKEN` и `OPENAI_API_KEY`.
- История спора передаётся выбранной модели OpenAI.
- Бот тренирует аргументацию и не заменяет юридическую, медицинскую или финансовую консультацию.
- JSON-лидерборд подходит для небольшого проекта; при высокой нагрузке его лучше перенести в PostgreSQL.
